
\chapter{Introduction}\label{ch:ch01:introduction}

\Gls{ai} has made substantial progress in recent decades. Modern \gls{ai} methods solve problems across a wide range of domains: they classify images~\citep{HeEtAl16}, process natural language~\citep{DevEtAl19}, plan sequences of actions to achieve goals~\citep{GerSer02}, verify hardware and software systems~\citep{BraMis10,ClaEtAl04}, and search for high-quality solutions to difficult optimisation problems~\citep{KhaEtAl17}.
More recently, large language models (LLMs) have revolutionaised the world with their ability to solve complex tasks, such as automated coding~\citep{CheEtAl21}.
Algorithms that solve these problems are highly sophisticated, based on decades of human research. This thesis is concerned about empirical performance prediction of AI algorithms. The task might be unfamilliar to many people. However, is plays an important role in the unseen background of many real-world applications. In the following, we will explain the meaning of the sentence by first understanding the meaning of the terms, understanding the settings of the task (the inputs and outputs) and explore use-cases.

Empirical performance prediction is an important task on the meta-algorithmic level~\citep{HutEtAl14}. The term has three components, each important in its own right. First, ``empirical'' means that the task is based on observations and real-world measurements rather than theoretical analysis. As such, factors such as algorithmic stochasticity and hardware dependencies are part of the problem. Second, ``performance'' refers to a metric that measures how well an algorithm solves a task. For example, accuracy measures how well a machine learning model performs on a classification task, while running time is a common performance metric for solvers of hard computational problems. The choice of metric is crucial as it should capture what the user cares about and be measurable through empirical trials. Finally, ``prediction'' means estimating an performance of an algorithm on a given task without actually running it on that task. This is done using features that describe the problem.

Next, we explore the settings of empirical performance prediction. In general, the task involves a target algorithm that we aim to predict its performance. The algorithm operates on \textit{problem instances}, which are intialisations of the problem the algorithm solves (such as datasets for a machine learning algorithm). Each instance can have \textit{instance features}, which are (cheaply) computed features that can be computed to describe the instance. Based on these features, an empirical performance model (EPM) can predict the performance of an algorithm on the instance. However, performance prediction is not limited to this setting. In many cases, (AI) algorithms are parametarised, \emph{i.e.}, they have (hyper)parameters that control their behviour, for example, how fast the a machine learning model learns from the data, or which heuristic to use to solve a problem. Therefore, another possibility is to use the (hyper)parameter configurations of the algorithm as an input to the EPM in order to predict the performance on unseen configurations. An additional setting uses a combination of the instance features and configurations as an input~\citep{HutEtAl14}.

At this stage, we understand the meaning of empirical performance prediction. Therefore the next task is to explore how it is used. 
As previously mentioned, there are many algorithms that can solve each problem.
An example is the Boolean satisfiability problem (SAT), where many solvers participate each year in the SAT competiotion, aiming to be the fastest SAT solver on a set of several hundreds of instances. Examining the 2026 SAT competition, 33 solvers were submitted, while the single best solver was the fastest only on $9.8\%$ of the instances, and selecting the best algorithm for every instance would yield performance more than $2.8 \times$ faster than the single best solver (full details of the analysis is available in Appendix \todo{}).
Therefore, automatically selecting the best solver for each problem instance is an important task. In fact, algorithm selection-based solvers have won multiple SAT competitions~\citep{XuEtAl08,KadEtAl11}.
Algorithm selectors usually work by extracting features of the problem instance and giving them as an input to an EPM, based on its prediction the algorithm is chosen~\citep{XuEtAl08}.

Additional use-case of EPMs is to tune parametrised algorithms. As previously introduced, algorithms depend on (hyper)parameters that affect their performance. Careful tuning of these parameters for the use case can substantially improve the performance of algorithms~\citep{HutEtAl06,HutEtAl11}. To show the importance of tuning, we use data from TabArena~\citep{EriEtAl25}, a large scale benchmark of machine learning methods for tabular data. TabArena contains the performance various models on multiple datasets, including the performance of verious hyperperameter configurations. We analysed this data and found that the popular LightGBM~\citep{KeEtAl17} model can have more than $40\%$ better performance using a tuned configuration compared to the default one. Therefore, tuning algorithms for the given tasks is an important field of research. A common procedure for tuning algorithms is to use EPMs to predict the performance of the algorithms on unseen configurations and using these predictions to decide which configuration to sample next~\citep{HutEtAl11,SnoEtAl12}.

The final use-case we will dive to in this thesis is explainability of algorithms. There, EPMs are used to predict the performance of the algorithms on configurations and/or instances, and, based on these, calculating which (hyper)parameters and features are more important, which values lead to good performance and more~\citep{HutEtAl14b,MooEtAl21}.

We note that, in this thesis, we have a relatively wide view on what EPMs are. While a narrow definition can classify EPMs as only models that predict the actual, numerical metric value of the algorithm, we have a broader view that includes indirect predictions as EPMs as well. For example, in algorithm selection \textit{pairwise classifier} does not predict the performance of the algorithms but rather has a few models that classify between pairs of algorithms which one is better~\citep{XuEtAl12b}. We view such models as performance predictors as they are still used to predict which algorithm has better performance, thus indirectly predicting the performance of the algorithms.

By this point, we hope that we convinced the reader regarding the importance of EPMs in research and practice. In the following sections, we will explore shortcomings of EPMs and overview the contributions of thesis.

\section{Obtaining Better Representations of Problem Instances and Search Spaces}
\sectionmark{Representations of Instances and Search Spaces}

As previously introduced, an EPM uses information about problem instances and algorithm configurations to predict performance. When predictions are made across instances, descriptive features provide this information. Such features have supported performance prediction, algorithm selection and configuration in \gls{sat} for many years (see, e.g., \citealp{NudEtAl04,XuEtAl08,HutEtAl11,HutEtAl14}). However, their usefulness depends on whether they can be computed reliably within the available budget. The widely used SATzilla feature extractor had become difficult to apply to contemporary instances: solvers, preprocessors, instance sizes and computing systems had changed substantially since its implementation. Compilation problems, memory requirements and hard-coded time limits could prevent features from being computed at all~\citep{ShaHoo24}. This limits the information available for prediction, selection and explainability.

An additional representation problem arises with high-dimensional data and search spaces. Dimensionality reduction can make learning and optimisation more tractable by mapping inputs to a lower-dimensional space~\citep{CunGha15,LetEtAl20}. However, information useful for clustering or classification need not support objective-value prediction or search. In black-box optimisation, this matters when few observations are available and evaluations are expensive. Furthermore, different surrogate models provide different approximations of the same search space, and their suitability can change as observations accumulate~\citep{HofEtAl11}. Choosing one approximation in advance may fail to exploit these differences. These issues motivate our first question: \emph{How can we obtain better representations of problem instances and search spaces?}

To address this question, we first revisit the infrastructure used to compute SATzilla features. We introduce a modernised feature extraction tool that replaces outdated preprocessors and solvers, resolves compilation and memory issues, and allows the user to set feature computation time limits. We evaluate both the availability of the resulting features and their usefulness for satisfiability prediction, running time prediction and algorithm selection. On the evaluated instances from the 2022 and 2023 \gls{sat} Competitions, the updated features improve the reported results on all three downstream tasks. The cost of extraction nevertheless remains dependent on the feature group and instance. This contribution shows that improving the inputs to an EPM can begin with making established features more accessible and informative. We present this work in \cref{ch:ch04:rev_SATzilla}, based on
\begin{itemize}
    \item \fullcite{ShaHoo24}
\end{itemize}

Next, we assess which information should be retained when reducing the dimensionality of data or a search space. We benchmark dimensionality reduction methods through four downstream tasks: clustering, tabular classification, target function approximation and black-box optimisation. By varying the original and target dimensionalities and the observations available to learn a representation, we evaluate its usefulness under different conditions. The results show substantial performance complementarity: success on one task or in one data regime does not establish suitability for another. This makes the choice of dimensionality reduction method itself an algorithm selection problem and motivates evaluating representations through the task they are intended to support. We present this study in \cref{ch:ch05:dim_red}, based on
\begin{itemize}
    \item \fullcite{ShaEtAl25}
\end{itemize}

Finally, we investigate how the approximation of a search space can adapt during optimisation. Here, the connection to representations is through the surrogate model: it describes how configurations relate to performance, and different model families capture different aspects of that relationship. We introduce DyMBO, which dynamically combines or selects complementary surrogates using their ranking quality on all observations accumulated so far. An exponential moving average controls how the history of model weights affects subsequent choices; its greedy selection variant retains only the currently preferred surrogate. In the tested hyperparameter optimisation settings, adapting surrogate choice improves average performance over static choices and the compared optimisation frameworks, with greedy selection between a Gaussian process and a random forest particularly effective. These results depend on a suitable portfolio, and fitting multiple models adds computational cost. DyMBO thus contributes a method for adapting the surrogate-based approximation of the search space, extending the task-dependent representation perspective of the preceding work. We present it in \cref{ch:ch06:dymbo}, based on
\begin{itemize}
    \item \fullcite{ShaEtAl25d}
\end{itemize}

\section{Building and Assessing Predictive Models and Surrogate Models}
\sectionmark{Predictive Models and Surrogate Models}

Once a representation is available, a predictive model can use it to estimate performance and support algorithmic decisions. Established tabular EPMs can learn from hand-crafted instance features~\citep{HutEtAl14}, while surrogate models can guide the choice of configurations in Bayesian optimisation~\citep{Garnett23}. However, a tabular model receives summaries of an instance rather than the relationships from which those summaries were derived. For a Boolean formula, for example, statistics of variables and clauses may omit information that could be learned directly from their connections~\citep{SelEtAl19}. Developing predictive models that use this structure is therefore one way to improve performance prediction.

A separate issue is how to assess whether predictions are useful for the decision they support. Lower aggregate prediction error does not necessarily lead to better algorithm selection or optimisation~\citep{XuEtAl12b,ShaHoo25}. In Bayesian optimisation, the acquisition function uses predictions to decide which configuration to evaluate next~\citep{Garnett23}. An error that makes a suboptimal configuration appear promising can affect that decision more than a similar error elsewhere. This raises a question beyond the choice of model architecture: which aspects of predictive accuracy matter for the search? We therefore ask: \emph{How can we build better predictive models and surrogate models?} We approach this question both by developing predictors and by investigating the consequences of their errors.

First, we study graph neural networks as EPMs for \gls{sat} solvers. We construct a benchmark for running time prediction and algorithm selection, and compare several graph representations and neural architectures with tabular models using SATzilla features. Models with and without supplied node features allow us to examine the information learned from relational structure. On the evaluated small instances, the strongest graph configurations improve both running time prediction and solver selection over the reported tabular baselines. The strongest overall results use node features, showing that learned structure and hand-crafted information can complement each other. However, memory requirements restrict the graph-model evaluation to small instances. Moreover, timeouts are represented by penalised running times; these targets do not recover the unknown completion times of right-censored runs. The contribution establishes the usefulness of graph-based prediction within this scope, while leaving scalability and broader generalisation open. We present this work in \cref{ch:ch07:gnns_epms}, based on
\begin{itemize}
    \item \fullcite{ShaHoo25b}
\end{itemize}

Next, we investigate where surrogate predictions need to be accurate for Bayesian optimisation. We introduce a noisy-oracle framework that controls mean-prediction errors in different regions of the search space. This allows us to study their effect on optimisation while holding other aspects of the surrogate fixed. The experiments provide evidence that accuracy in regions with good objective values is more useful than concentrating accuracy solely around the optimum according to distance. At the same time, errors elsewhere must not make suboptimal configurations appear misleadingly good. A theoretical analysis derives conditions under which such errors cause the considered acquisition functions to prefer a suboptimal point. This provides a more precise account of why global error alone does not explain optimisation success. The study is a first step: its main oracle uses fixed predictive uncertainty and does not learn from accumulated observations, so it does not establish how a particular training procedure will improve a learned surrogate. We present this work in \cref{ch:ch08:noisy_oracle}, based on
\begin{itemize}
    \item \fullcite{ShaHoo25}
\end{itemize}

\section{Making Performance Prediction Easier to Understand, Compare, and Use}
\sectionmark{Understanding, Comparing, and Using Predictions}

As discussed in the opening of this chapter, EPMs can also help us understand algorithm behaviour. Explaining which features affect a prediction can reveal properties associated with good or poor performance. However, predicting and explaining a single statistic, such as mean running time, leaves out run-to-run variation. For randomised algorithms, this variation can matter when users care about consistency or the risk of a long run. Distributional predictors can capture it~\citep{EggEtAl18,TueBur21}, but their parameters are not always directly interpretable. We therefore need explanations that relate instance features to meaningful properties of the predicted distribution, including its scale, variability and tail behaviour.

There is also a practical barrier to using and comparing performance prediction methods. Algorithm selection and configuration methods have often been developed in separate communities, with implementations tailored to \gls{sat}, planning, machine learning or black-box optimisation. Existing tools support parts of these workflows~\citep{Kotthoff13b,LinEtAl15,LinEtAl22b}, but combining methods through a common interface and applying them to another domain can require substantial implementation effort. This makes comparisons and reproduction more difficult. These interpretability and software issues motivate our third question: \emph{How can we make performance prediction easier to understand, compare, and use?}

To gain insight into randomised algorithm behaviour, we introduce a framework for explaining full running time distribution predictions through interpretable statistics. We use mean, variance, interquartile range, skewness and kurtosis to connect distributional predictions to permutation importance and individual conditional expectation analyses. We also introduce a tree-based XGBoost approach to parametric distribution prediction. Its evaluation against DistNet~\citep{EggEtAl18} shows lower final-fit computational cost, while relative predictive quality depends on the scenario, observation budget and distribution family. In the studied \gls{sat} and planning scenarios, the explanations show that features associated with typical running time need not also explain variability or distribution shape. These explanations concern the fitted predictor and remain conditional on the features, distribution family and available observations; they do not establish causal effects on solver behaviour. We present this work in \cref{sec:ch09:dist_explain}, based on
\begin{itemize}
    \item \fullcite{ShaHoo25c}
\end{itemize}

To make methods easier to compare and apply, we introduce \gls{asf}, a problem-agnostic Python library for constructing, benchmarking and applying algorithm selection pipelines. Its common interface operates on instance features and algorithm performance data, bringing together selectors, portfolio pre-selection, pre-solving, feature processing and automated configuration. We evaluate these components through machine learning case studies and ASlib scenarios~\citep{BisEtAl16}. The results show that pre-selection can improve selection quality as well as reduce training cost, and that the best pipeline components vary across scenarios. Making these alternatives available as reusable components supports comparisons across domains and reduces the effort required to apply established methods to a new task. It still requires informative features, representative data and an appropriate evaluation protocol. We present this contribution in \cref{ch:ch10:asf}, based on
\begin{itemize}
    \item \fullcite{ShaHoo25d}
\end{itemize}

\section{Structure of the Dissertation}

The order of the dissertation follows the dependency structure of empirical performance prediction.
Part~I introduces empirical performance prediction, algorithm selection, Bayesian optimisation, and the problem domains and benchmark scenarios used in the contribution chapters.
Part~II, \emph{Better Features}, starts with the inputs to performance models: reliable hand-crafted features, task-aware dimensionality reduction, and adaptive information about which surrogate models are appropriate during optimisation.
Part~III, \emph{Better Models}, then studies how to improve the models themselves, from graph neural empirical performance models to surrogate models whose accuracy is aligned with optimisation performance.
Part~IV, \emph{Better Insights}, asks how these methods can be explained and used more broadly, through distribution-level explanations and reusable algorithm selection software.
Finally, Part~V synthesises the results and discusses how the contributions fit together into a broader view of empirical performance prediction as a practical tool for building more adaptive \gls{ai} systems.
